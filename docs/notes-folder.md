# The notes folder

Your notes folder is a folder of **your own Markdown files**: an Obsidian vault, the folder of Nextcloud Notes, a git repository, a folder of notes. The configuration names it with `case_store`, its first key, kept so that every configuration reads as before. Sioul links to the notes and never owns them: you, or an AI agent helping you, keep writing in your files as before.

Sioul's own lists are plain files too: the projects (`sioul-projects.toml`, below), budgets and bank accounts (`sioul-budgets.toml`, `sioul-bank.toml`: [accounting.md](accounting.md)), money movements (`sioul-movements.toml`), contracts (`sioul-contracts.toml`), the clients' profiles for invoices (`sioul-clients.toml`: [projects.md](projects.md#clients)), the papers' list (`sioul-papers.toml`: [papers.md](papers.md)) and the letters' list and texts. Every release before the move kept them at the root of the notes folder, with the papers' files in its `papers/` and the scanned letters in its `letters/`. Once a device has moved them (below, "What lives where"), they are in Sioul's data folder, the papers and letters in folders of their own, and the notes folder holds the person's notes alone.

A project is any matter you follow: a tax return, a health-cover request, a bill to contest, or work for a client ([projects.md](projects.md)). Its detailed record lives in your notes.

## Where it is set, and when there is none
- **Set on the Notes page**, the first row of its ⚙ ("The notes folder", the configuration's `case_store`), above "New notes go into". It is this device's own (`CONFIG_LOCAL` in the sharing): each device says where its copy is. Settings ▸ Sharing keeps one line saying which folder it is, since your notes travel from it, with a button to that row; every link to it by its key (`settings:case_store`, the Porch's own door, the sharing's line) opens it there (`settings::page_of`, `SettingDoor.qml`).
- **Its state** (`Config::notes_folder`): ready (set, and it reads), unreadable (set, and `read_dir` fails: a drive not plugged in, a folder moved or renamed), or unset (none set; on Android, `~/Notes` counts as set once it reads). The window holds it as the property `notesFolder` (JSON: `{"state", "path"}`), found off the window's thread at the start, when the folder is chosen, and at each minute, so that a drive plugged in is seen within a minute and a drive that does not answer never holds the window.
- **Asked for in the Notes page's place** while it is not ready (`FolderNeeded.qml`), never an empty list: unset, one sentence on what the folder is (plain Markdown notes that stay yours, which other programs may open and sync, which Sioul links to and never owns); unreadable, the folder by its path, and why it may not read. Under it, "Choose a folder…" ("Choose again…"), which opens the system's folder chooser right there; on Android, Sioul's own (`FolderBrowser.qml`), which asks for "All files access" as the sharing's chooser does. Chosen, it is written as `case_store` and the page fills; refused, the reason is said under the button. Tested by `tst_folderneeded.qml`, and on the real page at 1400 and at 412 points by `tst_mailopen.qml`.

## The manifest
One file among Sioul's lists, `sioul-projects.toml`, names the projects (example: [../examples/sioul-projects.toml](../examples/sioul-projects.toml)): in `records/` of the data folder once the device moved, at the root of the notes folder before. A project's `files` stay named from the notes folder's root, wherever the list is.

```toml
[[project]]
id = "taxes-2025"            # short and stable: tasks, events and notes refer to it
title = "Income tax 2025"    # shown in the interface
files = ["admin/taxes-2025.md"]   # the record, relative to the notes folder's root
status = "open"              # open, waiting, closed

[[project.route]]            # which mail belongs here
from_domains = ["impots.example"]

[[project.route]]
from_domains = ["hospital.example"]
subject_contains = ["certificate", "attestation"]
```

## Its first name
Before projects and cases became one thing, the file was `sioul-cases.toml` and each entry `[[case]]`. Nothing written then is lost (`sioul_core::projects`):
- **Read as before**: Sioul reads `sioul-projects.toml`, and `sioul-cases.toml` when only that one is there (`file_in`); `[[project]]` and `[[case]]` both read.
- **Written under the file's own names**: a change goes into the file read, under the table name it already uses, so that a device with an older Sioul still reads it. A new file is `sioul-projects.toml`, with `[[project]]`.
- **Renamed when you say so**: the Notes page's ⚙ ▸ "Rename to sioul-projects.toml" writes the file under the new names in one write, every field, route and comment kept, and checked to be so before anything is written; the old file stays beside it, as `sioul-cases.toml.before-rename` (`rename_file`). It is never done by itself: an older Sioul reads only the first name, so it waits until every device is updated.
- **Both files there**: Settings says so; Sioul reads `sioul-projects.toml` and leaves `sioul-cases.toml` as it is.
- **Shared**: the sharing's records keep the first names, `notes/sioul-cases.toml` and `case`, which every version reads; each device writes them into its own file under that file's names ([database.md](database.md)).
- **Addresses**: a project is `sioul:project/<id>`. `sioul:case/<id>`, as Sioul wrote it before, opens the same project, wherever it is written: a note, `links.toml`, a task, an agent's request. A note's front matter `case: <id>` still ties the note to the project.

## Routes
- **A message belongs to a project** if any of its routes matches.
- **A route matches** when every list it fills has at least one match:
  - `from_domains`: the sender's domain or any subdomain ("finances.example" covers "dgfip.finances.example", not "notfinances.example");
  - `from_addresses`: an exact address, case ignored;
  - `subject_contains` and `text_contains`: whole words or phrases, case and accents ignored;
  - `attachment_contains`: words in an attachment's file name ("devis" takes `Devis_2026.pdf`), case and accents ignored.
- **Several projects may match**: the first in the file is the message's home; the others are listed as "also concerns".
- **A conversation follows its project**: a message that answers or cites one of a project's (In-Reply-To, References), or one tied to it by hand, goes to the same project ("in a conversation of this project"), unless it was set aside, is a code or is hostile.
- **Mail is tied to its project when it arrives** (`links.toml`, `mid:` ↔ `sioul:project/`, `how = "project"`), so the project's page shows it whatever the route needed (the text, an attachment) and later replies follow it. Changing a project's routes ties the mail already here that its text or attachment routes take, as the Porch would take it (`porch::Gate::routed`): never what it sets aside. A tie you make by hand is `how = "link"`.
- **The Porch's checks hold everywhere a project takes mail** (`porch::admission`): its lanes, a project's page, the ties made when routes change, the agents' `list_projects` and what agents may read of each project (`consent::Consent::of`), the project a task made from a message is given. What it sets aside joins no project; what nothing authenticates joins by no route on its sender.
- **Every routing keeps its reason** ("sender's domain: impots.example"), shown on request.
- **Routes are edited** on the project's page ("Mail that comes here by itself") or in the Porch's lane for the project.

## In the standards
- A project's tasks and events carry its id in `X-SIOUL-REFID` (RFC 9253's `REFID` under Sioul's own name, which a phone's account manager can send back: [compatibility.md](compatibility.md), "A phone's ical4j"; `REFID` is read too), so other CalDAV clients keep the grouping.
- Notes refer to messages by `mid:` URIs (RFC 2392) and to tasks, events, contacts, projects and drafts by `sioul:` addresses (`sioul:task/<UID>`), in a Markdown link or the front matter ([tasks.md](tasks.md)). Sioul reads the folder as a vault: wikilinks, links back, tags.
- `sioul projects` lists the projects and flags files the manifest names but that are not there (`sioul cases`, its first name, still works).

## What lives where
Sioul's own lists leave the notes folder for a place of their own, once on each device, on the person's word, so that the notes folder holds the person's notes alone. Code: `sioul_core::storage` (the places, the move, the take-out), `sioul_sync::share` (the gate, the moved stores, the guard), `crates/sioul-app/src/storage.rs` and `qml/StorageMove.qml` (the window). Decided on 18 November 2026: papers and letters in `Documents/Papers` and `Documents/Letters` by default; nothing taken out of the notes folder until every device has moved, and then (19 November, after the review) only on the person's press, each old file against its copy; the papers' and letters' folders empty when chosen; the lists travel by Sioul's sharing alone afterwards; they stay plain text files, editable by hand (a database would be another work).

### The places

| Thing | Before the move (every release before) | After this device moved |
|---|---|---|
| Lists: projects (`sioul-projects.toml`, or `sioul-cases.toml` and its `.before-rename` copies), client profiles, budgets, the bank's lines, movements, contracts, the papers' list | the notes folder's root | `<data>/records/`, under the same names (`~/.local/share/sioul/records/` on Linux) |
| The letters' list and texts | `letters/letters.toml`, `letters/<id>.txt` in the notes folder | `<data>/records/letters/` |
| Papers' files | `papers/…` in the notes folder, `file = "papers/x.pdf"` | the papers' folder (`[papers] folder`, `Documents/Papers` by default), `file = "x.pdf"` |
| Letters' scans and the folder scans arrive in | `letters/<year>/…`, `letters/inbox/` in the notes folder | the letters' folder (`[letters] folder`, `Documents/Letters` by default), `file = "<year>/…"`, `inbox/` (unless `[letters] inbox` names another) |
| Lock files | beside each list, in the notes folder | beside each list, in `records/` |
| A project's notes | `files`, from the notes folder's root | unchanged |

- **One way to read them** (`Config::places()`): `Places::under(notes)` before the move, `Places::apart(records, notes, papers, letters)` after; lists are read from `records_root()`, the notes themselves still from `notes_root_path()`. Before the move a device with no notes folder has no lists; once moved, the lists need none.
- **Paths read both ways** (`Docs::path_of`): a device moved and one not yet read each other's `file` fields (`papers/x.pdf` and `x.pdf`), since the papers' list travels between devices at different steps; a path written by hand from the notes folder is still found; an absolute path stays as it is.
- **Where this device stands**: `storage.toml` in the state folder (`Storage`: `moved`, `from`, `cleaned`), read by `Config::load`, never from `config.toml`, so that nothing that travels can move it. Gone while the journal is closed (`Journal::switched`) and every copy it names is there: the move is taken as made (`adopted`) and the file written again (`Storage::recover`), nothing copied or deleted. A file there that does not read, a journal that does not read, or a closed journal whose copies are not all there (a papers' folder on a drive not plugged in): `Storage::lost`, never "not moved" (the old files may be long gone) nor "moved"; `Config::places()` is then none, the sharing reads and writes no list, papers, letters or notes (`stores_of`), no move starts, and Settings ▸ Sharing and the window say what is missing (rule 3: absence proves nothing).
- **Defaults**: the documents folder as each system names it; on a phone, the folder the notes are in when they are on its shared storage, else Sioul's own storage, never a shared folder Sioul could not list without "All files access".
- **The papers' and letters' folders** are each device's own (`CONFIG_LOCAL`), set in Papers ▸ ⚙ and Letters ▸ ⚙ (`settings::for_view`, views `papers` and `letters`), read only once moved. A folder chosen there goes through the move's own checks (`check_folders`, resolved; an emptied row refused). Chosen again after the move, it must be empty or not exist yet; `storage::move_documents` then copies every file to it and checks each byte for byte, switches the setting with every exchange held, then names the list's absolute paths into the old folder from the new one. The old folder stays as it was. The notes folder chosen again once moved is checked against them too (`app::storage::check_notes_folder`).

### The gate
- **Each device says what it knows** in its sealed entry (`devices::Entry::storage`): 1 (`STORAGE_KNOWS`) once its Sioul knows the new places, 2 (`STORAGE_MOVED`) once it moved.
- **Nothing moves anywhere until every other device that counts says 1** (`share::storage_stand`; `present`: not left, not forgotten, not said replaced, heard from within 180 days). An older Sioul would go on editing the copy left behind, so the window names it and asks to update it. With no sharing set up, there is nothing to wait for; a sharing set up whose key the keyring does not give now (`StorageStand::unreadable`) opens nothing, as a device missing would (`app::storage::move_gate`).
- **The window** (`StorageMove.qml`) shows itself once, when the move is open and this device has not moved (`offer`, the view flag `storage-move-said`, set by any close); Settings ▸ Sharing has a line saying where the lists are, and "Where Sioul keeps its lists" opens it at any time; a move begun and not finished (`storage::begun`, or a failure said in this run) shows one card on the Porch that opens it. It says what moves and where, what stays under `papers/` and `letters/`, the two folders to choose and, under each, a sync program known to carry it (`share::carrier_of`); "Move every device the same day" with the devices still to move. Nothing moves before "Move now". With no sharing set up, it says that lists carried until then by a synced notes folder will no longer travel, and asks to set up the sharing on each device first. A notes folder set and not read now (`Config::notes_folder`, unreadable) holds the move and the window's own showing; one unset has nothing to move.

### The move, and what makes each step safe to stop
1. **Plan** (`survey`, `plan`): only what Sioul's lists name. The lists at the notes folder's root (the projects' file under both names, its `.before-rename` copies); each `[[paper]]`'s `file` under `papers/` (relative `papers/x`, absolute inside it, or a bare `x` found there and not at the root, as `Docs::path_of` reads it: `old_place`); the letters' list, each `[[letter]]`'s `<id>.txt`, and its `file` under `letters/` unless `linked`. Everything else under `papers/` and `letters/` (a note, a scan not read yet in `inbox/`, a text no letter has) stays and is listed (`Survey::left`). A notes folder that does not list, or holds nothing at all (an unmounted mount point), refuses (`notes-unreadable`, `notes-empty`); a list that does not parse refuses (`list-unreadable`). A link on the way to a file to move is refused (`plain_below`). `check_folders`: each folder absolute and its own, compared as resolved (`resolved`: links, `..`, case), none inside the notes folder nor holding it, none inside Sioul's own folders nor holding them. `check_empty`: the papers' and letters' folders hold nothing but what this move's journal says it wrote there (hidden files passed over): everything in them is shared by Sioul.
2. **Copy** (`fill`): each file goes through a hidden name beside its place (`.<name>.sioul-move`), its bytes synced, compared with the source byte for byte, dated as the source; then the journal (`storage-move.toml`, in the state folder) names it as this move's, synced, **before** it is renamed into place. Whatever is at a copy's place and is not this move's by its journal is refused (`records-taken`), never adopted; a place that is the source itself under another name (`same_file`) is refused. Stopped anywhere, the hidden copy is removed at the next run, and a file the journal names that holds its bytes is the move's own. A journal entry no longer planned (its source removed between two tries) keeps its copy and its dated copy (`Entry::alone`), said.
3. **Check** (`check`): every copy against its source, byte for byte, again.
4. **Dated copy** (`keep`): `<data>/moved/<day>/<path>`, a copy of its own (`std::fs::copy`: a copy-on-write clone where the file system gives one), flushed, checked to be another file with the same bytes. Never a hard link: an editor writing the old file in place would write it too.
5. **Paths named** (`name_paths`): in the copies of the papers' and letters' lists only, a record whose file the move copied takes its path in the new folder (`named_from`, by `old_place`); any other is unchanged, checked to change nothing but `file` fields (`same_but_files`). The journal notes the new bytes' SHA-256 before the file is replaced.
6. **Switch** (`switch`), with every exchange held (`hold_exchanges`: this Sioul's own exchanges told to hurry and waited for, and the exchanges' lock) and every old list's own lock held: planned again, what came since is copied and checked; each source is looked at again (a list by its bytes, a paper or a scan by size and time); one changed since its copy is copied again, checked, kept, its paths named again; then the journal is closed (`switched`), then `storage.toml` is written, synced: **the one step after which the device reads the new places.** Its entry then says 2.

- **The whole move holds the move's own lock** (`storage-move.toml`'s lock file): two Sioul on one device never move at once, nor take out while moving.
- **A failure before the switch** (`move_now`) takes back what this run made, and only that (`undo_run`: marks kept in memory, never on disk): a copy it made while its source is still there with the bytes copied, the dated copies it made, the folders it left empty. Never a copy an earlier run made. The old places were never touched, and the window says why in one sentence naming the file (`storage-*`, `$what`). **Killed instead**, nothing is taken back, and the next run finishes, tested at each of about fifty points (`each_point_stopped_then_run_again_finishes_once`). A closed journal is never work to do again (`open` refuses it).
- **The sharing never takes the moved stores for new ones**: each says where the memory knew it before (`Store::was`), honoured in the first exchange that reads them all after the move (`Memory::relocated`), so that a change made just before the move and not sent yet goes out, never replaced by an older record (`two_devices_at_different_steps_stay_in_step`).

### The take-out
- **Only on the person's press**: once this device moved, Settings ▸ Sharing shows "Sioul's old files are still in your notes folder" with their count (`storage::old_files`) and "Take them out" (`app::storage::take_out`), greyed until every device that counts says 2 (or none is known), naming those still to move. Nothing takes them out by itself, nothing guesses whether a sync program carries the notes folder, and no device is chosen to do it.
- **What** (`clean`, rule 1): an old file goes only when it is as copied, reached through no link (`plain_below`), not the same file as its copy, its copy at the new place as a plain file reached through no link (`Journal::reached`), and the same bytes at that moment: a paper's or a scan's copy itself; a list's dated copy (its copy in `records/` changes by use). Any other stays, said by why (`Cleaned::changed`, `Cleaned::kept`). Then its lock file, then `papers/` and `letters/` once empty, never through a link. A notes folder that does not read takes out nothing.
- **Said done** (`Storage::cleaned`, `Journal::cleaned`) only once nothing is left; the dated copies go thirty days after that (`sweep_kept`, after each exchange and each minute's look), never while the old files are still there.
- **An old file changed after the switch** (`changed_since`: size and time, then bytes) is named on the Porch once per change, merged with nothing; the take-out leaves it.

### How they travel afterwards
- **Sioul's lists travel by the sealed sharing alone**, in the part "projects" (Projects and money), which once moved also carries the papers' list and the letters' list and texts (before: in "papers" and "notes"), so that they are on wherever sharing is on and never refused for a carried folder. Their records keep their names (`notes/sioul-cases.toml`, `notes/sioul-papers.toml`, `files/notes/letters/letters.toml`, `files/notes/letters/<id>.txt`). The part is on by default once moved (`shared_by_default`), but a recorded "off" stands, so the window offers to switch it on, ticked, saying why (`app::storage::move_now(…, carry)`).
- **Papers' files** travel in "papers" under `files/papers/…`; **the letters' scans** under a name of their own, `files/letters/…` (`LETTERS_FILES`), since their list and texts kept the old prefix in the records; it is written only once every device knows it (the gate), and `known_part` lets a device not moved pass those records over. "papers" is refused while a sync app carries the papers' or the letters' folder (`app::share::carried_for`): one carrier for a file.
- **The notes folder's switch** "a sync app carries my notes" then speaks of the notes alone; the old files that stay there until the take-out are left out of the notes part (`NOT_NOTES_MOVED`), and so is any folder named `papers` or `letters` at its top, for good: those names stand for Sioul's records.
- **A device that does not know the new places** (an older Sioul, one forgotten or silent that comes back) may take a list it can no longer follow for one emptied and send its elements out as removed: on a moved device, removals that would leave one of Sioul's own lists with one element at most, two or more being there, from a device whose entry does not say 1, are held for good (`list_removals_held`, `Memory::lists_held_there`), said (`share-list-held`); an element that comes back with a value ends its hold.

### The guard
A list this device read before, now gone or of no bytes but blanks, is never read as "everything taken out": [database.md](database.md), "Sioul's own lists". What no guard brings back: a change written to a list and not sent yet when that list is lost on its device.

### Trying it
`sioul move-lists --notes … --records … --papers … --letters … --kept … --state …` runs the move on the folders given, without the window or the sharing: a trial on a copy of real files. Every folder is given; the command refuses any that is, holds or sits inside this device's own configuration, data or state folder, or its notes, papers or letters folder, as each resolves (`storage::clash`). `--plan` lists `from → to` and what stays, without copying; `--clean` then takes the old files out, each against its copy. Afterwards every list in `records/` equals its source byte for byte, except `sioul-papers.toml` and `letters/letters.toml`, whose `file` fields are named from their new folders. Tests: `crates/sioul-core/src/storage_tests.rs` (the move on stand-in folders made from `tests/fixtures/old-layout/`), `crates/sioul-sync/src/share_lists_tests.rs` (the guard), `share_move_tests.rs` (devices at different steps, an older build, offline through the move, a removal carried, a whole list's removal from a device that does not know the new places).

### Limits
- **A writer that took the old path before the switch** and waited on that list's lock writes the old file after the switch: that change stays in the old file, named on the Porch, not in the new one.
- **A list removed and written again with one entry** by a Sioul writer before the next exchange looks is taken as that one entry: the guard sees only gone or blank files.
- **A device whose lists travelled only by a notes folder's sync** (part "projects" off) diverges from the moved devices until it moves too; when it does, its part goes on and it joins, the records' values winning for an entry both changed. The window says to move every device the same day.
- **Between the moves of two devices**, a scan made on one reaches the other only once both moved; its list entry comes at once.
- **Tasks' and events' `file://` links to a scan** (made by "A task for that date" and "Into the agenda") are not rewritten: they live on CalDAV servers, and an event may be a meeting. Opened, a link that points under the old `papers/` or `letters/` opens the moved file, from the move's own journal.
- **A device that sent a whole list's removal while it did not know the new places** keeps its own view of that list until an element changes on a moved device: its removals are held there, not undone everywhere.
- **A blank letters' list** written again from the records leaves a "(conflict …)" copy of the blank file beside it.
- **On Windows**, `sync_dir` does nothing; on Android without "All files access", a notes folder lists only what Sioul made, and a file not seen counts as not there for the take-out.
