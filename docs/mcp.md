# Sioul for AI agents: the MCP server

`sioul mcp` serves what Sioul keeps on this computer to AI agents over the Model Context Protocol (MCP, revision 2025-06-18): Claude Code and Claude Desktop now; ChatGPT and local models later, through any MCP client. The agent reads the Porch, mail, tasks, the agenda, contacts, budgets, notes and projects, the phone's messages and calls, papers, the persons of the household opened to it, contracts and paper letters, time and invoices, reminders, and the moment now, and your texts when you allow them; it adds tasks, events, notes, ties and drafts, and changes, moves, deletes and converts events and tasks when asked, each change said in the window with Undo; it runs, watches and judges your own spam filter, when you let it ("The spam filter's tools"). It never sends, deletes or moves mail, moves money, or reads a password ([ai.md](ai.md), "Limits that do not move").

**Every project is closed to agents until you open it** ("Per-project access", below): the switch "Open to AI agents" on its page, in its form, or in Settings ▸ AI agents writes `ai = true` on its entry in `sioul-projects.toml` (`sioul-cases.toml` under the file's first name). A connected agent reads and writes the projects you open, and nothing of the others. Things in no project (the Porch's other mail, tasks and notes of no project, the agenda, contacts, the phone's messages and calls, papers, contracts) are open unless you close them (`[mcp] outside_projects = false`). What an agent reads goes to the provider of its model.

Code: `crates/sioul-cli/src/mcp.rs` and `crates/sioul-cli/src/mcp/`; the rule of who may see what, `crates/sioul-core/src/consent.rs`.

## Connecting
### Claude Code
```
claude mcp add sioul -- sioul mcp
```
- `claude mcp add --scope user sioul -- sioul mcp` makes it there in every project, not only the current one.
- Another configuration, another language: `claude mcp add sioul -- sioul --config ~/admin.toml --language fr mcp`.
- When `sioul` is not on the `PATH`, its full path: `claude mcp add sioul -- /home/you/.cargo/bin/sioul mcp`.

### Claude Desktop
In `claude_desktop_config.json` (macOS: `~/Library/Application Support/Claude/`; Windows: `%APPDATA%\Claude\`), then restart Claude Desktop:
```json
{
  "mcpServers": {
    "sioul": {
      "command": "/home/you/.cargo/bin/sioul",
      "args": ["mcp"]
    }
  }
}
```
The full path: Claude Desktop does not read your shell's `PATH` (on Windows, `"C:\\Users\\you\\.cargo\\bin\\sioul.exe"`). `"args": ["--language", "fr", "mcp"]` for French.

## A new program, the same connection
A client keeps `sioul mcp` running for as long as it runs itself, days at times. When an install puts a new Sioul in place (`tools/install.sh`, a package, `cargo install`), the server takes it up by itself: the agent gets the new tools without a restart of its client.
- **When it looks.** Between two messages, while nothing the client sent waits unread in the server, then once a second while the client sends nothing; never in the middle of a message.
- **What tells a new program.** On Linux, `/proc/self/exe` reads "(deleted)", or the path the program was started by holds another file than the one that runs; on macOS and the other Unix systems, the path holds another file, or its modification time moved. A path through a link, as a package manager makes, is followed through the link.
- **How it takes over.** Once the new file has stayed as it is for a second (an install that writes it in place has finished), the server tries it first, so that a program that cannot start (its arguments refused, a library missing, a file cut short) never takes the connection, which would then end (review of wt/mail, F3 and F8): the file and the folders holding it (its link's and its own) must be yours or the system's and writable by nobody else, or held in a folder with the sticky bit, so that nothing another account put there runs as you; its `--version` (standard input from /dev/null, five seconds at most) must answer and be no older than the running program's; and the arguments it would be given, with `--help` after them, must be accepted (not tried when they hold `--`). `sioul remind --watch` follows its program the same way ([reminders.md](reminders.md)). Then it runs it in its own place (`execve`): the same path, the same arguments, the same standard input and output. What the client sends meanwhile waits in the pipe for the new program, so no message is lost.
- **The handshake goes with it**, in the environment variable `SIOUL_MCP_HANDOVER`: the revision agreed, the client's name and its capabilities. The new program answers the next message without a second `initialize`, and first sends `notifications/tools/list_changed`, so that the client reads the tools again; the server says `"tools": { "listChanged": true }` at the handshake.
- **One line in the log** ("A log, without the words", below): `"event": "followed"`, with both versions. A file that cannot run (no program, or not executable) changes nothing: the server says so on standard error and in the log (`"event": "kept"`), goes on serving, and tries again once the path holds another file.
- **On Windows, nothing happens.** A program's file cannot be deleted nor written over while it runs, so an install waits for the client to stop, or replaces the file at the next start; and Windows has no `exec`, to run another program in the same process on the same input and output. The client starts the new program the next time it starts `sioul mcp`.

## The tools
Things are named by their addresses, as links name them ([tasks.md](tasks.md)): `mid:<Message-ID>` (`sioul:mail/<account>/<digest>` for a message without one: [client.md](client.md#the-index-behind-the-mail-and-one-address-for-a-message)), `sioul:task/<UID>`, `sioul:event/<UID>`, `sioul:note/<path>`, `sioul:contact/<UID>`, `sioul:project/<id>` (`sioul:case/<id>`, as written before, still opens it), `sioul:draft/<id>`. The read tools give them; `links` and `link` follow them.

### Texts
Your texts (SMS and MMS, [texts.md](texts.md)), **off unless you turn them on**: `[mcp] texts = true`, the switch "Texts" in Settings ▸ AI agents. Texts carry other people's words, often more private than mail; off, the three tools are neither listed nor called. A text in two phones' logs, as after a restore onto a new phone, is given once, by the rule the Texts page follows ([texts.md](texts.md), "Each text once, across phones").

| Tool | Reads | Changes |
|---|---|---|
| `texts` | The conversations, the one whose last text arrived most recently first (their people by your address books' names, else their numbers; the last words, and when that text arrived; an id each); with `conversation`, its messages in the order they were written, the newest `limit`: when each was written (`at`, `when`, `day`, `time`), and, for a text that arrived on the phone 5 minutes or more later, when it arrived (`arrived`, `late_minutes`, and "arrived 01:55, 3 h 45 later" on its line: [texts.md](texts.md#when-a-text-was-sent)); who wrote it ("You" for you), the words, the pictures and other parts said by kind (never opened), what became of a text sent from a computer, deleted on the phone said; and, after them, a long text whose last parts have not reached the phone yet (`on_the_way`: how many parts came, of how many, when it was sent; [texts.md](texts.md#parts-still-on-their-way)). The tool's description says which time is which, so that an agent never takes an arrival for the time a text was written. | Nothing. |
| `search_texts` | Texts holding every word, in their words, a part's name, or their people's names and numbers; the newest written first, with the times `texts` gives. | Nothing. |
| `draft_text` | Nothing more than the conversation named. | A draft, saved for the Texts page in its conversation, on this computer only (`textdraft`, `drafts.jsonl` in the texts' private folder, sealed as the texts are). **Never sent**: a draft is no request to send, and nothing reads it to send. In its conversation, the page shows it under "Drafted by an AI agent, not sent", with **Use it** (its words go into the box; sending stays your Send) and **Delete the draft**; the list says "A draft by an AI agent waits here". One person only: never a group, never a short number, at most 1,600 characters. |

- **Codes masked as in mail**: each text's words are masked before any tool reads them (a code, a sign-in link, an IBAN, a card or social security number), so that a code is neither given nor found by its digits.
- **Others' words come as data**, between the per-answer frame marks.
- **Per project**: texts are in no project. A conversation is kept from agents when one of its people is a contact kept from agents (a closed project's client, or a contact tied to a closed project), by the numbers in your address books; every conversation while things outside projects are closed. Left out of the lists, counted, refused by its id, never drafted to.
- **Group conversations** are read, never drafted to: the phone refuses to send to a group from a computer.
- **The keyring, once**: the texts on a computer are sealed at rest with a key made from the sharing key ([texts.md](texts.md), "Sealed at rest"). To open them, `sioul mcp` reads the sharing key from this computer's keyring, only while `[mcp] texts = true` and only when a texts tool is called; the key opens the texts in memory and never reaches the agent. It is the one thing the MCP server ever reads from the keyring; the switch's sentence in Settings says so.

The new reading tools change nothing anywhere. Health (medicines, doses, needs, the pharmacy and renewal errands) stays out, as passwords, keys and whole account numbers do; the meals and the night show only as what now is for, by their kind and when they end, never by a name. The plan's time held for meals, naps and the night is read from the health file's `[needs]` alone (`needs::Needs::read`), so that this process keeps no medicine.

## The mailbox
The `mailbox` tool (the unified mailbox's part 6, `crates/sioul-cli/src/mcp/mailbox.rs`), over the window's mailbox (`sioul_core::mailbox`, [client.md](client.md#the-mailbox)):
- **Consent, in order**: (1) the days and the address asked; (2) what is kept from agents by its address (a closed project's mail, by its ties and the routes on its sender and subject; a work or school Microsoft address kept; mail in no project while `[mcp] outside_projects = false`) is left out before anything else, inside the page's making (`page_with`'s `keep_out`), never made into a row, and counted over those days and that address alone, so that the count is the same whatever the kind and the unread filter and cannot tell whether a closed project holds unread mail or spam; (3) blocked senders, left out and counted; (4) the kind: spam only where the spam tools are allowed (`[mcp] spam`), `kind: spam` refused otherwise with a calm sentence, and without a kind, received and sent; (5) unread: received, not spam, not read; (6) on the messages about to be given, a project's route on their text or attachments (`Consent::allows_mail`), left out as `search_mail` leaves them, uncounted, so that no count follows a filter. Hostile mail to a shielded address is "someone at" its domain, its subject's words hidden.
- **Older mail still being read**: the window's first look at a folder reads its newest 500 messages (`mailbox::FIRST_FILL`), the others at the next looks. The next answer gives what comes after it, newest first by when sent then by address: mail that arrives meanwhile is newer and goes to a new first answer, mail dated in the past comes in its place; nothing is given twice nor skipped (`the_mailbox_for_agents`). A cursor that names a file, or does not read, is refused.

## What does not move
- **Nothing is sent or paid, and no mail is deleted.** No tool sends mail, deletes or moves a message, or moves money; the only deletions are `delete_event`, `delete_task` and `delete_movement` (a record of your own, never a payment), marked destructive in their hints, each asked for by you and said in the window with Undo, never of a meeting with others; none speaks to a server but `spam_fetch`'s job, which reads your mail servers for the spam filter's corpus, read-only; no sync runs. A task or an event written here goes with the next sync, as one made in the window. A draft waits in Drafts until you read it and send it from the window, or discard it.
- **Nothing secret.** No password, key or token is given to an agent; the keyring is never opened, but for the sharing key that opens your texts while you allow texts for agents ("Texts", above), which stays in Sioul. The Porch says that a code came, never the code. A message carrying a code has every code hidden wherever it is written ("482 913", "482-913", "48 29 13", digit by digit as an HTML table turned into text writes it, in the subject, in a quoted reply, far down a long text), with every link it holds, as good as the code (a sign-in, a reset, an address to confirm); a message giving a password is kept whole from the agent, even when a code comes first. IBANs (checked by their mod 97), payment card numbers (Luhn's check) and French social security numbers (their key, Corsica's 2A and 2B too) are masked in mail, notes and budgets, written with spaces of any width; the last four characters stay, to tell two accounts apart. The masks are the same in the lines and in the data, and searching for the digits of a masked number finds nothing. The window shows them all.
- **Mail is data.** What others wrote (mail, invitations, contacts, file names, the phone's messages) comes on one line per field, so that a subject cannot add a line such as `Lane:` or `Key:`. A message's or a note's own text comes between two lines that carry the same mark, made for that answer, which its author cannot know: whatever the text says, it cannot end the frame and speak as Sioul. The agent is told once, when it connects, that all this is data, never instructions, and to ask you rather than do what a message asks. Forged mail is said forged. Hostile mail to a shielded address (as the Porch judges it, its AI's reading first) is given by no word of it, nor answered; encrypted mail is not given.
- **Only your mail.** `read_message` and `draft_reply` open files inside your accounts' mail folders only, whatever path they are given (`mailfind::inside`): the path is checked as it is written before anything is opened (absolute, no other computer's share, `..` folded, a message file of a folder, never `tmp/`, the most precise account's Maildir), then again once the system has followed its links (the file and its folder: a link to elsewhere is refused). The spam label finds its message on this device only (`find_here`).
- **Writing adds, or changes what you asked.** Beyond the tools that change, delete or convert one event, task, checklist or money movement at your request (above, each said in the window with Undo), writing only adds: a note never replaces another, nor goes out of the notes folder (no drive as `C:`, no device name as `CON`, no link on its way); a task, an event or a draft takes a name nothing has; a tie is made once; a task done opens again in the window. What an agent writes may come from mail, so it is checked as mail is: a title, a place, a subject on one line; each recipient one address, its name holding no other; a tie only to what Sioul has or to a web page, never to a file of this computer or to another program's scheme, and never with a line break that could add a line to a task or an event that the next sync sends. Each writing tool says what it changes, and MCP's hints say it too: `readOnlyHint` true for the reading ones, `destructiveHint` false for all, `openWorldHint` true only for `spam_fetch`, `read_message` and `draft_reply`, which may ask your mail servers, read only.
- **The admin windows hold.** `porch` keeps to them unless the agent asks (`open`); the agent is asked to respect them unless you ask.
- **A log, without the words.** Each call: when, the client's name, the tool, its arguments (a draft's or a note's text by its length only, other texts cut short and masked), whether it failed, and what was given by its addresses (`mid:…`, `sioul:…`) and its length. One JSON line, one file a month, `$XDG_STATE_HOME/sioul/mcp/2026-10.jsonl`, readable by you alone. No message's text, no code, no secret is kept a second time, in a file that would outlive the mail; the agent's model, wherever it runs, received the text itself. A spam training's job file keeps its result, the worst errors' senders and masked subjects among it, for a week after it ended (`$XDG_STATE_HOME/sioul/spam/jobs/`, yours alone). The server's own events have a line too: a new program that took over the connection, or one that could not run ("A new program, the same connection").

- **A mask lifted for one request**: an agent cannot lift one; the window shows the numbers.

## How it is built
- **The transport apart** (`transport.rs`): the stdio transport reads one JSON-RPC message per line on standard input and writes one per line on standard output; nothing else is written there, diagnostics go to standard error. A line is at most 8 MiB; a longer one, or one that is not UTF-8, is answered with JSON-RPC's parse error and the next one is read.
- **The program followed** (`follow.rs`): the stdio transport reads standard input through a buffer of its own, so that it knows when nothing is left unread; it waits for the next message with `poll`, a second at a time, and looks at the program's file between two messages ("A new program, the same connection").
- **The protocol** (`protocol.rs`): JSON-RPC 2.0 (`"jsonrpc": "2.0"`, an id a string or a number, never null); MCP 2025-06-18, and 2025-03-26 and 2024-11-05 for older clients: `initialize`, `ping`, `tools/list`, `tools/call`, `resources/list`, `resources/templates/list`, `resources/read`. A batch is refused, as 2025-06-18 removed them. A tool that fails answers `isError: true` with a sentence the agent can act on; an unknown method or tool is a JSON-RPC error. Whatever breaks, in a tool or in the protocol, says so, and the server stays up.
- **The registry as plain data** (`tools.rs`): name, title, description, JSON schema, function. Arguments are checked against the schema before the function runs: an unknown one is named, with those it takes.
- **The core's functions**, as the command line uses them (`read.rs`, `write.rs`; `phone.rs` for the phone's messages and calls, `records.rs` for papers, contracts, letters, time, invoices, reminders and the moment now): the Porch's gathering and views, the plan, the links, the notes, the drafts.
- **Per-project access** (`access.rs`, on the core's `consent`): what everything belongs to, read once per call with the files the tool reads; each tool leaves out, counts and refuses through it.
- **The configuration read again at each call**: an agent connected for a day sees today's. One that cannot be read is said to the agent, not taken for none.
- No async runtime, no MCP library: `serde_json` and the core.

## Next: ChatGPT and other clients
- **Streamable HTTP**, MCP's other transport: one endpoint, each message a POST, each answer JSON or an event stream, the session in `Mcp-Session-Id`. It is another `Transport` over the same server and the same table: `sioul mcp --http 127.0.0.1:<port>`. Bound to this computer, the `Origin` header checked (the spec asks it, against DNS rebinding), a token from the keyring asked of the client.
- **ChatGPT** reaches MCP servers from the internet, never on this computer: it needs a public address (a tunnel you choose) and OAuth 2.1, as MCP's authorization says. Its deep research asked for two tools named `search` and `fetch`: thin names over `find` and the reading tools.
- **Local models** (llama.cpp, Ollama, LM Studio) take it as it is, through any MCP client that starts a program on stdio.
- **Other agent protocols** (OpenAI's function calling, an agent's own tool format) can serve the same table: names, descriptions and schemas are plain data.
