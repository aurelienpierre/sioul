# Languages

Sioul speaks your language, English and French first. **The core decides and returns facts** (lanes, reasons, counts), and **one translation layer turns them into sentences** (`crates/sioul-core/src/i18n.rs`).

How to read and write the `.ftl` files, and how the code asks for a message: [Strings: Fluent](fluent.md).

## Why Fluent
Translations use [Project Fluent](https://projectfluent.org/), Mozilla's system.
- **It handles agreement as well as plurals.** French must say "une lettre est arrivée" but "un code est prêt"; gettext's plural forms alone cannot express that.
- **Each language decides its own grammar** in its own file: the code passes the number, and the number in words in the masculine and the feminine, and each language picks what it needs.

## Files
- **One file per language**: `crates/sioul-core/locales/<language>/sioul.ftl`, built into the program.
- **English stands in** for any message a translation lacks.
- **A test checks** that every language has every message, and that every file parses.
- **`tools/check-messages.py`** checks that every message the code asks for by its name (QML `sioul.text("…")`, Rust `text("…")`, `say("…")`) exists in each language, and French typography (narrow no-break spaces, ’); `--unused` lists the messages never asked for by name (some are built at run time, "area-" and a kind). It fails when something is missing, so CI runs it.

## Conventions
- **Counts**:
  - `$n` is the number, for plural selection;
  - `$count` and `$Count` are it in words, lowercase and capitalised;
  - `$countf` and `$Countf` are the feminine forms;
  - small numbers are written as words, as a calm sentence says them.
- **Short-lived secrets**: `$kind`, `$Kind`, and `$akind` with its article ("a code", "un code").
- **Typography belongs to each language**: French puts a narrow no-break space before `:` `;` `!` `?`, and uses typographic apostrophes and commas in decimals.
- **Plain, literal language in every language**: no idioms, buttons that say what they do ([research.md](research.md), §10).
- **"Device" and "computer"**: "device" wherever a text says where data stays or which of your machines does something; "computer" only in a contrast with a phone, for a part that exists on computers only (Qt WebEngine's sites; the command line and the agents' `sioul mcp`, whose texts say "this computer", since 3 November 2026: `mcp::tests::the_agents_texts_say_this_computer`), for the kind of program Sioul is (a desktop application), and in measurements made on a computer. French follows the same rule with « appareil » and « ordinateur ».
- **A kind of thing is « type » in French**, never « sorte » ([attention.md](attention.md), decision 26; the tests of `attention.rs` check it).

## Dates and numbers
Day and month names come from the translation files for now. Full regional formats (CLDR, through ICU4X) come when a language needs more than names and separators.

## Detection is not the interface's language
The detectors (one-time codes, dates in letters, projects' routes) read the languages of the mail you receive, whatever the interface's language. The code detector reads French and English today.

## The Qt interface
QML displays strings it gets from the core: one catalogue, not two.

## The command line
`sioul --help` and each command's help come from the code's comments, in English, as clap writes them. Since 10 November 2026 they are written in the session's language where it has the words (`crates/sioul-cli/src/help.rs`):
- **The language** is read from the arguments as given, before clap reads them (`--language X` or `--language=X`, and `--config X` for the configuration's `language`, anywhere before `--`), else the configuration's, else the session's, as for the rest of the command line.
- **The words**: `cli` for the program's about, `cli-<command path>` for a command's (`cli-remind`, `cli-mail-send`), `cli-<command path>--<argument>` for an argument's, its `_` written `-` (`cli-remind--watch`, `cli-event--all-day`; `cli--language` for a global option); and the few clap writes itself: `cli-heading-usage` ("Utilisation :"), `cli-heading-commands`, `cli-help`, `cli-help-more`, `cli-help-summary`, `cli-version`, `cli-help-command` and `cli-help-command--subcommand`. They live in each language's `sioul.ftl` but English's, whose words are the comments: a text without a message keeps its English (`Translator::own`, which never falls back to English for another language).
- **The structure** is clap's own: the same sections in the same order, the same commands and options in their columns; only "Usage:" is written by a help template of clap's default shape with the heading in words ("Arguments" and "Options" read the same in French). Errors stay clap's, in English.
- **Tests** (`help::tests`): every text of the help has its French and every French message names a text of the help (`every_help_text_has_its_french`: a new option needs its French); English is clap's help word for word, French has its shape line by line (`the_help_in_french_keeps_its_structure`).

## Translating
- **AI drafts the missing strings**, marked for review, then a person checks them (the workflow Ansel's documentation uses).
- **Weblate** supports Fluent, for when translators join.
